功能使用统计

入口：记录 → 就诊资料 → 使用统计；或 我的 → 反馈与帮助 → 管理员运营看板。
开发/体验环境或演示模式显示本机调试数据；正式版仅服务器授权的管理员显示入口。
管理页面：packages/operations/analytics；pages/analytics/analytics 保留兼容跳转。
v3.1 新增发送诊断和反馈回复，详细口径、保留策略与交付状态见 docs/operations-v3.1.txt。

范围与口径
- 当前已发布路由的入口点击、筛选/切换、模块访问，及底部导航点击。
- 保存记录/档案/护理/用品/相册、生成回答、生成结果与带码图片、收藏、导出和保存到相册等成功节点。
- 业务捕获的已接入失败分支、未捕获的交互错误、权限/网络/超时等分类。
- 完成按业务节点计数；保存到本机与云端同步是不同状态。一项操作可能对应多个完成节点。
- 分享统计只代表打开分享入口，不能证明发送成功、收件人收到或扫码打开。
- 页面每次真正进入计一次访问，内部数据刷新不重复计数；弹层模块首次打开也计访问。
- 正式人数使用云函数获取的当前微信身份经 SHA-256 转换后去重；客户端不能指定用户身份。
- 本机调试显示设备数，不能当作正式用户人数。
- v2 新增独立的流程、渠道、新用户和留存汇总，不能用总点击直接推算转化率。
- v3 已增加首页入口可见曝光、配对点击率，以及云同步、图片生成和导出文件的耗时/结果；详见 docs/operations-v3.txt。
- 尚未统计一般页面停留时长和分享实际送达，未做 A/B 分组。

数据边界
固定枚举：模块、动作、事件类型、异常分类、来源渠道、系统类型、首页入口、操作及结果；时间、版本、耗时、随机事件/会话/流程/曝光 ID。
不收集输入文字、聊天内容、照片、宠物健康资料、城市或地址、分享对象等内容。
开发/体验/演示事件只在本机保存近30天汇总，不上传正式库。
正式事件最多缓存200条；7天后过期。每批8条、约15秒批量上报，失败退避重试；服务端仍兼容旧版最多20条。
云端按“当前用户＋事件 ID”去重，只确认已保存的条目；统计失败不能阻断业务。
统计会受离线过久、清缓存、设备退出及缓存上限影响，不是账务审计数据。

云端部署
1. 将 utils/analytics-catalog.js 同步为 cloudfunctions/pet-analytics/catalog.js。
2. 完整部署 cloudfunctions/pet-analytics，使用远程安装 wx-server-sdk 4.0.2。
3. pet-analytics 的 status 返回当前调用者的 viewerId。通过可信的开发者工具获取自己的 ID。
4. 将允许查看全局统计的 viewerId 写入云函数 admins.json 数组后重新部署，
   或配置云函数环境变量 ANALYTICS_ADMIN_IDS（多个 ID 逗号分隔）。
   前端不可写此配置；默认空列表、拒绝所有全局统计读取。不自动授权第一个访问者。
5. 云函数首次收集时创建 pet_usage_events_v1。云数据库安全规则配置为：
   {"read": false, "write": false}
   对应 database.rules.json；这是控制台配置参考文件，上传云函数不会自动应用数据库规则。
   由云函数服务端访问。禁止向客户端开放整个集合。汇总另外排除客户端直写的 _openid 记录。
6. cloud/analytics-indexes.json 中的 12 个索引已于 2026-10-10 创建并回读核验。当前汇总支持1/7/30天。
7. 小程序需发布包含埋点的新版之后，才开始产生正式用户数据；旧版本历史点击无法补采。

权限与发布
管理员权限独立于宠物档案的“主人/共同照护者”角色。普通用户即使直接打开统计页也不能读取全站汇总。
统计页不展示去重标识或原始个人事件；用户分组仅用于服务端聚合。
我的 → 反馈与帮助 → 使用数据说明，解释用途、字段与去重标识，并可关闭后续使用统计、清除待上传事件。
反馈正文只在用户主动提交时上传，用户只能读取自己的反馈，管理员可查看全部反馈并调整状态。
正式发布前同步更新微信后台隐私保护指引；应用内说明不替代后台配置。

维护
新增页面需使用 utils/analytics-page.js 的 instrument 包装，并更新 analytics-catalog 中的交互白名单。
新增完成/异常节点使用 analytics.track / analytics.failure；禁止把输入值或原始错误文本作为事件动作。
云函数与客户端目录中的 catalog 内容需要保持一致。

运营看板 v2（本地实现：2026-10-10）
- 概况：所选时段内活跃用户、首次被新版统计到的用户、期间老用户、完成日常新增记录的用户及每日活跃趋势。
- 第1/7天留存：以所选时段的首次使用用户为队列，按北京时间自然日计算精确第N天是否活跃；第N天完整结束后才进入分母。未成熟队列显示待观察，不记作0%流失。选择近30天可观察第7天留存。
- 首次使用指首次被v2统计到，不等于安装日期；旧版本的未知历史无法补齐。离线补报可修正首次日期和来源。
- 记录流程：打开新增表单 → 提交 → 本机保存成功；编辑旧记录、历史演示记录不算新增完成。云同步异常保留在基础错误明细。
- 趣味流程：进入制作页 → 生成结果 → 带码图片生成 → 打开图片分享入口。直接访问好友结果页不补造前置步骤。
- 出行流程：每次列表查询 → 查看详情或直接收藏 → 收藏或复制地址。取消收藏不算完成，空结果另外记录empty_results。
- 流程按独立流程ID计数，支持中途返回；各阶段必须按时间顺序发生，基准是第一步的流程数，不是不同操作的总次数相除。
- 本机调试保留最近30天最多3000条事件及一个设备的活跃快照；超过上限会提示流程数据可能不完整。云端不采用此条数上限。
- 来源为首次可识别入口；age_card/personality_card/bingo_card对应现有图片小程序码（scene仍为工具名，无需改码服务）。分享链接自动添加src=age_share/personality_share/bingo_share/outings_share/family_share。
- 人工推广可在既有路径查询参数追加src=xhs、src=community或src=offline。例如pages/play/play?tool=age&src=community。只接受白名单，不上传任意参数、完整链接、推广文案或分享对象；没有标记的外部流量不推断为小红书。
- 来源表显示该队列的新增人数、完成记录比例及第7天留存；不是逐个分享者的邀请奖励或送达证明。
- 版本取wx.getAccountInfoSync().miniProgram.version；开发版无版本时记develop。版本表只显示事件量，尚未提供按版本筛选的对照实验。

存储和权限
- 沿用已锁定的pet_usage_events_v1集合，不增加客户端直读权限。现有原始事件结构继续兼容；基础明细仅匹配原有五类kind。
- recordType=visitor：首次日期/来源、最近120天活跃日期和新增记录日期、留存标志；文档ID为op_user_加服务端用户哈希。
- recordType=flow：各步骤最早时间、连续完成到哪一步、开始日期、版本；文档ID由当前用户和流程ID联合哈希，跨用户不会合并。
- recordType=feedback：主动反馈正文、类型、模块、版本、系统和状态。recordType=feedback_quota：每日提交限额（5条）。
- 事件先按用户＋事件ID去重落库，快照使用事务合并；快照完成后才确认批次。重试使用数据库已保存的事件，不用重复请求覆盖已存内容。
- 推荐上线索引：day升序；recordType+lastDay；recordType+firstDay；recordType+startDay；recordType+createdAt降序+_id降序；反馈列表常按状态/用户筛选时添加recordType+status/uid+createdAt降序+_id降序。
- 当前云函数配置为20秒。客户端缩小批次，接口失败仍退避重试，不阻塞业务。
- 活跃日期数组会在用户再次上报时裁剪；原始事件、流程快照、反馈和限额文档尚未自动清理。扩大运营规模前需配置保留周期和清理任务，首次日期/来源摘要应单独保留，以免回访误算新增。

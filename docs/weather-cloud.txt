天气云端查询 · 2026-10-11

原因与方案
- 用户真机天气不可用；在开发者工具启用 setting.urlCheck 后，Open-Meteo 与 BigDataCloud 均返回 request:fail url not in domain list。用户提供的后台截图也显示尚未配置服务器域名。
- 前端保留隐私检查与 wx.getFuzzyLocation 授权，把两位小数的大致坐标交给独立 pet-weather 云函数。天气不再从手机直接请求 Open-Meteo，不依赖该 request 域名配置。
- 城市识别仍使用合法的 BigDataCloud 客户端接口；这个免费接口不迁到服务器。客户端未配置该域名或解析失败时显示“当前位置”，温度和降水查询不受影响。模拟器明确显示“模拟器位置”。

实现
- 新函数目录 cloudfunctions/pet-weather，使用现有相同版本 wx-server-sdk 4.0.2；无数据库写入、无 OpenAPI 权限、无定时任务。
- 服务端从微信调用上下文取得 OPENID，不使用客户端提交的身份；校验坐标范围并保留两位小数。上游地址与参数固定，不支持客户端 URL。
- 上游仅接受 HTTP 200 JSON，响应最多 128 KiB，总请求时限 8 秒；拒绝无效、明显过期和未来天气，仅返回页面所需字段。
- 实例内天气缓存 10 分钟，最多 128 处位置、32 个并发位置；同一位置并发合并。缓存不写库，不将坐标、账号或上游密钥写入业务日志。
- utils/weather.js 按既有云环境调用 pet-weather；缓存、授权撤回、定位失败和天气新鲜度规则继续保留。明确显示云服务未连接、查询超时、服务繁忙和数据更新中的状态，不用示例天气作为真实结果。
- 初次完整部署前，需用户允许开发者工具部署 pet-weather。云端成功后，核对函数运行超时配置足以覆盖上游 8 秒限时，再验证调用与开域名校验后的页面。
